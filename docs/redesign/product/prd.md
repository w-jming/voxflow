# PRD:VoxFlow 下一代本地流式语音输入法

> **编号** VF-PRD-01 · **版本** 0.3 · **状态** 评审中(决策已回填,待冻结) · **最后更新** 2026-06-10

术语见[术语表](../glossary.md)。需求明细见[需求规格](requirements.md)。未决事项见[审查与待决策](../review-and-decisions.md)。

## 1. 产品定位

VoxFlow 是面向 Linux 优先、后续跨平台的本地语音输入法。它的核心价值不是"把语音文件转成文字",而是在任何可输入文本的位置,以输入法级体验把用户正在说的话实时转成文字。

下一代版本采用 Rust Core + Tauri 控制台 + 输入法前端的三进程架构,目标是让 VoxFlow 具备真实桌面软件的完整性:安装后可用、输入反馈清晰、模型可管理、错误可诊断、数据可迁移、隐私可控。

## 2. 目标用户

| 用户群 | 核心诉求 |
| --- | --- |
| 中文/英文混合输入用户 | 在浏览器、聊天工具、编辑器、终端、文档软件中快速输入 |
| Linux 桌面用户 | 离线可用,不依赖云端语音服务 |
| 长文本创作者 | 长时间连续听写,能自然说"不是""不对""删掉刚才那句"进行修正 |
| 多设备用户 | 后续在 macOS 和 Windows 获得同一套输入体验 |

## 3. 当前版本(0.2.0 Python/GTK)的核心问题

1. **伪实时**:采用"录音结束后识别"模型,无法 token 级流式输出。
2. **反馈位置错误**:顶部系统通知承担了实时输入状态反馈,干扰且不可靠。
3. **控制台单薄**:更像设置表单,缺少状态工作台能力。
4. **撤销不可靠**:语义撤销停留在规则和局部账本阶段,缺少意图分类、安全门和可解释记录。
5. **边界混乱**:输入法、模型管理、后台服务、控制台之间职责不清,难以演进到跨平台。

下一代版本解决的是这些架构性问题。按 D-7 裁决,旧 Python 版本直接废弃(无旧版用户,无迁移负担),新版从零按[实施计划](../engineering/migration-plan.md)实现。

## 4. 产品目标

### P0(MVP 必须交付)

- token 级流式输出:partial → stable → final 三级事件。
- 临时文本、稳定文本通过输入法 preedit/commit 显示在光标处;听写状态由**全局状态指示器**实时显示,不使用 preedit 占位文案(D-12 裁决,见[交互设计 §1](../frontend/interaction-design.md))。
- Linux IBus 输入法模式,可在主流桌面应用中输入。
- Linux Fcitx5 输入法前端,与 IBus 能力对等(D-15 裁决,覆盖 KDE/wlroots 系桌面)。
- Rust Core 与 Tauri 控制台分离,通过版本化 IPC 通信。
- 默认本地运行,不上传音频和文本。
- 简体、繁体、模型原文三种输出字形。
- 智能撤销:规则状态机 + 轻量意图分类器 + 账本安全门,默认开启、可关闭。
- 模型下载、导入、校验、切换在控制台中可完成。
- 控制台支持浅色、深色和跟随系统主题,切换不影响输入会话。
- deb 和 portable 包安装后即可用,不要求用户手动装 Python/Rust 依赖。

### P1

- 高准确率模型对 final segment 异步精修。
- 多麦克风选择、蓝牙耳机 profile 诊断与一键切换。
- AppImage 包。
- macOS 输入通道原型(spike)。

### P2

- Windows TSF 原型。
- 多语言 UI。
- 用户自定义词典、领域热词。
- 可选云端模型接口,默认关闭。

## 5. 非目标

- 不做云端 SaaS 服务、多人同步、会议转写。
- 不以通知气泡、浮窗遮罩替代系统输入法 preedit。
- 不把大模型权重默认安装到 `/usr`、`/opt` 等系统目录。
- 不向普通用户展示未实现的实验后端。

## 6. 成功指标

所有延迟指标在**基准机**(见[术语表](../glossary.md))上、使用默认轻量流式模型测量。测量方法见[测试策略 §5](../engineering/testing-strategy.md)。

### 输入体验

| 指标 | 目标 | 测量口径 |
| --- | --- | --- |
| 首 partial 延迟 | < 500 ms (p90) | VAD 判定语音起点 → 首个 `dictation.partial` 事件 |
| stable commit 延迟 | < 1000 ms (p90) | token 产生 → 该 token 被 commit,正常中文语速 |
| 连续听写稳定性 | ≥ 10 分钟 | 无中断、无状态丢失、内存无持续增长 |
| 光标处可见性 | 100% | partial 在 preedit 中可见,不遮挡输入位置 |
| 状态指示器更新延迟 | < 100 ms | Core 状态变化 → 指示器可见状态更新 |

### 准确率与修正

| 指标 | 目标 |
| --- | --- |
| "这不是问题"误触发撤销 | 0 次(固定负例测试集) |
| "三点,不对,四点"实体替换 | 正确替换,不影响其他文本 |
| "刚才那句删掉" | 只删除 VoxFlow 自己最近 commit 的片段 |
| 简繁输出 | 不依赖简单字表替换作为主要简繁策略 |
| 安全门后误删率 | ≤ 0.1%(固定测试集,见[分类器规范 §9](../architecture/semantic-intent-classifier.md)) |

### 安装与运维

- deb 安装、卸载、升级通过自动化容器测试。
- portable 包可解压到任意目录运行,不要求 root。
- 模型下载支持进度、速度、暂停、恢复、断点续传、失败重试。
- 本地模型导入必须通过结构和 checksum 校验,失败不污染现有配置。

## 7. MVP 验收清单

MVP 必须同时满足以下各项(括号内为对应需求编号):

1. Tauri 控制台可启动,显示 Core、输入法、模型、麦克风四类状态(FR-CC-01)。
2. Core 通过本地 IPC 接收命令并推送事件,断连后 UI 可重连(FR-CC-02、NFR-REL-03)。
3. IBus 前端在光标处显示 preedit 并 commit stable 文本(FR-INP-04)。
4. Fcitx5 前端与 IBus 能力对等,在 KDE 会话中通过同等验收(FR-INP-09)。
5. 全局状态指示器按环境降级矩阵实时显示听写状态(FR-CC-11)。
6. mock recognizer 与至少一个真实 streaming ASR 后端均通过流式测试(FR-INP-02)。
7. 规则状态机 + 轻量分类器 + 账本安全门可用,可关闭,误触发负例全部通过(FR-SEM-01~06)。
8. deb 和 portable 包安装后通过 smoke test(FR-PKG-01、FR-PKG-02)。
9. 三种主题模式可切换且不中断听写(FR-CC-09)。

任何一项不满足则不能宣布 MVP 完成;允许按[实施计划](../engineering/migration-plan.md)的阶段门逐步达成。

## 8. 范围裁剪规则

P0 范围若发生进度风险,按以下顺序裁剪(先裁后面的):

1. 不可裁剪:流式输出、IBus preedit/commit、Core-UI 分离、本地优先。
2. 可降级:意图分类器可先以规则状态机交付,分类器作为 P0.5 紧随(账本安全门不可裁)。
3. 可推迟:繁体输出、模型导入(保留下载)、主题跟随系统(保留手动浅/深切换)。
4. Fcitx5 属 P0(D-15 裁决);发生进度风险时推迟需所有者重新裁决,不得默认裁剪。

任何裁剪必须更新本文档版本号并记录在 PR 中。
