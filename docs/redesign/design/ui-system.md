# UI 系统设计

> **编号** VF-DSN-02 · **版本** 0.3 · **状态** 评审中(决策已回填,待冻结) · **最后更新** 2026-06-10

## 1. 设计目标

VoxFlow 控制台必须像一个真实桌面工具,而不是网页 demo 或简单设置表单。UI 的首要任务是帮助用户判断"现在能不能输入",然后才是配置模型、音频、快捷键和语义修正。

- **状态优先**:打开首页即可看到输入服务、输入法、麦克风、模型是否可用。
- **操作明确**:每个问题旁边提供下一步操作。
- **视觉克制**:天蓝色 `#0EA5E9` 为主色;避免绿色主调、大面积渐变和装饰性背景。
- **输入不中断**:控制台不抢焦点,输入中的状态在光标处显示。
- **跨平台一致**:三平台同一套信息架构与视觉语言。

### 2.6 动效

| Token | 值 | 用途 |
| --- | --- | --- |
| `--motion-fast` | 120ms | hover、按钮按压 |
| `--motion-base` | 160ms | 卡片状态切换、菜单展开 |
| `--motion-slow` | 240ms | 对话框、页面切换 |
| `--motion-ease` | `cubic-bezier(0.2, 0, 0, 1)` | 统一缓动 |

原则:动效只用于状态变化和输入反馈,不做装饰;下载进度与音频电平连续变化;错误状态不闪烁;`prefers-reduced-motion` 或用户设置"减少动效"时,全部过渡降为 0ms,仅保留进度类连续更新。

## 3. 布局

### 3.1 桌面窗口

默认 `1080 × 720`,最小 `900 × 600`;内容区最大宽度 920px,宽屏下居中,避免控件拉伸。

```text
┌──────────────────────────────────────────┐
│ Header: Logo / 全局状态 / 快速操作          │
├──────────────┬───────────────────────────┤
│ Sidebar 220px│ Page content (max 920px)   │
│ 总览          │ cards / forms / lists      │
│ 输入          │                            │
│ 模型          │                            │
│ 音频          │                            │
│ 语义修正      │                            │
│ 数据          │                            │
│ 诊断          │                            │
│ 外观          │                            │
└──────────────┴───────────────────────────┘
```

参考线框图:[control-center-wireframe.svg](assets/control-center-wireframe.svg)(注:线框图侧栏待补"外观"项)。

### 3.2 密度

- 首页 2 列状态卡片(< 1000px 宽时单列)。
- 设置页使用表单行(标签左、控件右),不使用营销式大卡片。
- 控件高度:紧凑 28px / 标准 32px / 大 40px;最小点击目标 32×32px。
- 列表项高度稳定;下载进度变化不得导致布局跳动(进度文本用 tabular-nums + 固定宽度槽位)。

## 4. 组件

### 4.1 状态卡片

结构:图标(24px)+ 标题(`--text-md`)+ 状态 badge + 一行说明(`--text-sm`,muted)+ 主操作按钮。

| 状态 | badge | 行为 |
| --- | --- | --- |
| 正常 | info 底 + `可用/运行中/已连接` | 主操作弱化为次级按钮 |
| 警告 | warning 底 + 下一步说明 | 主操作为实心按钮 |
| 错误 | error 底,仅用于当前功能不可用 | 主操作为实心按钮 + 诊断链接 |
| 降级 | info/warning 底,如"已降级为规则模式" | 附说明链接 |
| 加载 | 骨架屏或 16px spinner | 占位尺寸与就绪态一致 |

### 4.2 模型卡片

字段:模型名、类型(流式/精修/语义分类器)、语言、参数规模、许可证、本地状态、占用空间。操作:下载、暂停、继续、校验、切换、删除(删除为危险按钮 + 二次确认)。

### 4.3 下载进度

必须显示:模型名、目标目录、已下载/总大小、速度、剩余时间、当前阶段(下载/校验/安装/完成)。进度条高度 6px、圆角 3px、主色填充;阶段切换用文字而非颜色单独表达。

### 4.4 快捷键录入

点击进入监听态(边框主色 + "请按组合键")→ 显示规范化结果(`Alt+S` 形式,等宽字体)→ 冲突处理:与系统/输入法级快捷键硬冲突时 error 提示并阻止保存,与应用菜单助记键等软冲突时 warning 提示但允许保存 → 保存后 Core 热更新(FR-CC-03)。默认值 `Alt+S`(D-14)。

### 4.5 音频电平

实时电平条:主色→cyan 渐变填充;刻度标记过低(< -50 dB)、正常、削波(> -3 dB,端部转 warning 色);蓝牙仅输出 profile 时整条替换为 warning 状态 + 修复入口。更新 ≤ 20 帧/秒,`reduce_motion` 时降为 4 帧/秒。

### 4.6 语义修正记录

每条记录:原识别片段、意图 badge、删除目标(删除线样式)、替换内容、置信度(百分比,tabular-nums)、安全门结果、恢复按钮。

### 4.7 全局状态指示器(HUD)

独立小窗组件(交互与降级矩阵见[交互设计 §1.1](../frontend/interaction-design.md)):

| 项 | 规格 |
| --- | --- |
| 形态 | 胶囊,高 36px,宽 36px(收起,仅 Symbol)~ 160px(展开,状态点 + 电平 + 短文字) |
| 底/边/影 | `--vf-panel` 底(不透明度 0.96)、`--vf-border` 1px 边、`--shadow-2`、圆角 18px(全圆) |
| 状态点 | 10px 圆点:空闲 `--vf-muted`;听写中 `--vf-primary-500` 呼吸动画(1.6s 循环,reduce-motion 时静态);处理中 `--vf-cyan` 旋转;警告 `--vf-warning`;错误 `--vf-error` |
| 电平 | 高 4px 微型电平条,`500 → cyan` 渐变填充,听写中才显示 |
| 文字 | `--text-xs`,仅警告/错误态显示短语,≤ 12 个字符 |
| 主题 | 随控制台主题切换资产与 token;深浅模式同形 |
| 动效 | 状态切换 `--motion-fast`;出现/隐藏 `--motion-base` 淡入淡出 |

托盘图标使用同一套四态语义(形状 + 颜色双编码),保证两个通道表意一致。

## 5. 可访问性

- 图标按钮必须有 tooltip 和 accessible label。
- 文本对比度满足 WCAG AA(对照表见[主题系统 §7](theme-system.md))。
- 不依赖颜色表达唯一含义:badge 同时有文字;电平削波同时有文字标记。
- 全部控件支持键盘导航,焦点顺序与视觉顺序一致。
- 下载、错误、模型切换等状态变化通过 `aria-live="polite"` 区域可读。

## 6. 平台适配

三平台同一信息架构,平台状态卡片内容不同:Linux(IBus/Fcitx5、PipeWire)、macOS(InputMethodKit、CoreAudio、麦克风权限)、Windows(TSF、WASAPI、输入服务注册)。

## 7. 主题

支持跟随系统/浅色/深色;切换只影响 UI,不重启 Core、不中断听写、不改变输入法会话(FR-CC-09)。主题入口在"外观"页,header 更多菜单提供快捷切换。实现规范见[主题系统](theme-system.md)。
