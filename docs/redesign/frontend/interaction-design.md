# 交互设计

> **编号** VF-UI-02 · **版本** 0.3 · **状态** 评审中(决策已回填,待冻结) · **最后更新** 2026-06-10

## 1. 输入中反馈

反馈分两条通道(D-12 裁决:preedit **全局禁止**非正文占位文案,听写状态走全局状态指示器):

| 信息 | 通道 |
| --- | --- |
| 临时文本(partial) | 光标处 preedit(下划线样式,只含真实识别文本) |
| 稳定文本(stable) | commit 到输入框 |
| 听写状态(空闲/听写中/处理中/错误)与电平 | **全局状态指示器**(§1.1) |
| 修正过程 | preedit 短暂显示修正样式后执行删除/替换 |
| 后台异常 | 控制台 + 托盘 |
| 致命错误、权限缺失、下载完成/失败 | 系统通知 |

**禁止**用系统通知显示:开始录音、正在听写、正在识别、已输入——这些是输入过程的一部分。

### 1.1 全局状态指示器(P0,FR-CC-11)

一个小型常驻悬浮窗(HUD),由 Tauri 壳层作为第二窗口管理(实现见 [Tauri 控制台 §3.1](tauri-ui.md)),订阅 Core 状态与电平事件,更新延迟 < 100 ms。

**形态**:胶囊形小窗,默认停靠屏幕右上角;视觉规格见 [UI 系统 §4.7](../design/ui-system.md)。

| 状态 | 呈现 |
| --- | --- |
| 空闲(服务运行) | 静态 Symbol,低调中性色 |
| 听写中 | 主色呼吸点 + 实时电平条 |
| 处理中(加载模型/flush) | cyan 旋转指示 |
| 警告(降级、设备问题) | warning 色点 + 简短文字 |
| 错误 | error 色点 + 简短文字 |

**交互**:左键单击 = 暂停/恢复听写;右键 = 快捷菜单(打开控制台、停止服务、隐藏指示器);可拖动改变位置(支持的环境下记忆位置)。

**环境降级矩阵**(实时性要求不变,呈现位置降级):

| 环境 | 呈现 | 说明 |
| --- | --- | --- |
| X11(各桌面) | HUD 悬浮窗,任意定位 + 置顶 | 完整体验 |
| Wayland:KDE、wlroots 系 | HUD 经 layer-shell 锚定屏幕角 | gtk-layer-shell 集成 [待验证] |
| Wayland:GNOME | 托盘图标实时状态(无 layer-shell) | AppIndicator 扩展(Ubuntu 默认启用);指示器设置页显示降级说明 |
| 无托盘环境 | 控制台迷你模式窗口(用户手动放置) | 兜底 |

设置项(输入页):指示器开关、位置(四角)、仅听写时显示/常驻。

## 2. 快捷键

两种模式(FR-INP-06):按住说话(hold)/ 按一次开始再按一次停止(toggle)。

| 要求 | 规格 |
| --- | --- |
| 默认值 | **`Alt+S`**(toggle 与 hold 共用,D-14 裁决) |
| 录入 | UI 录入组件监听组合键并规范化显示(见 [UI 系统 §4.4](../design/ui-system.md)) |
| 冲突 | 内置冲突检测:系统/输入法级快捷键硬冲突阻止保存;`Alt+字母` 与个别应用菜单助记键的软冲突仅提示不阻止(口径见 [UI 系统 §4.4](../design/ui-system.md)) |
| 生效 | 保存后 Core 热更新,无需重启(FR-INP-05) |

首次启动向导提供一键改键入口。

## 3. 托盘

菜单项(FR-CC-07/08):

1. 打开控制台
2. 暂停/恢复听写
3. 当前模型(只读,点击跳模型页)
4. 开始/停止输入服务
5. 显示/隐藏状态指示器
6. 打开日志
7. 退出 VoxFlow

"退出 VoxFlow"必须停止后台服务、监听与模型任务,不能只关闭图标;三层退出语义见 [UJ-09](../product/user-journeys.md)。托盘图标与指示器同源四态:空闲 / 听写中 / 警告 / 错误(形状 + 颜色双编码);GNOME Wayland 下托盘是指示器的降级主通道,状态切换同样要求 < 100 ms。

## 4. 模型下载

下载交互必须显示明确目标:哪个模型、下载到哪个目录、来源链接、进度与速度、校验阶段、成功后是否切换(默认询问,不自动切换)。

按钮:下载、暂停、继续、取消、导入本地模型、校验。失败态显示具体原因(磁盘不足/来源不可达/校验失败)与重试按钮,对应 [IPC 错误码](../architecture/ipc-api.md)。

## 5. 数据目录迁移

用户修改 VoxFlow Home 时的向导流程:

1. 显示当前目录和新目录。
2. 估算需迁移数据量(配置/模型/日志分别列出)。
3. 选项:全部迁移 / 只迁移配置不迁移模型。
4. 迁移前 Core 暂停相关任务(下载、听写)。
5. 复制 → 校验 → 切换配置指向 → 提示旧目录处理方式(保留/删除,删除需二次确认)。
6. 迁移完成后 Core 重启并自动重连。

任何失败步骤可回滚到原目录,不出现"半迁移"状态。

## 6. 语义撤销交互

撤销发生时,控制台修正记录新增一条:原始识别文本、判断意图、删除目标、替换文本、置信度、是否通过账本校验(字段规格见 [UI 系统 §4.6](../design/ui-system.md))。

- "恢复上一条修正"按钮恢复最近一次;恢复也必须经过账本安全门,目标已不在原位时给出说明。
- 每条记录附"这是误触发"反馈按钮(`correction.feedback`),用于改进分类器数据集。
- 撤销被安全门拒绝时不打扰用户(原样输入),仅在修正记录中留痕,供用户排查。
